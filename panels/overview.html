Project Overview

FORGE is a web-hosted platform for Bayesian exploration of machine learning models. The mk_1 release ships with three reproduced, well-known results spanning very different domains: (1) music genre recognition using a CNN with Bayesian components, (2) phonon density-of-states regression, and (3) the ATLAS Long-Lived Particle (LLP) detection problem from high-energy physics. The reproductions are performed by the author ahead of time and preloaded onto the site — users do not retrain from scratch; they inherit working baselines with documented performance.

Three experiments are deliberate. The domains are intentionally heterogeneous (audio, condensed matter, particle physics) to demonstrate that the FORGE pattern generalizes across model classes; the author's prior familiarity with each one allows mk_1 to ship faithful reproductions rather than approximations; and shipping three instead of one is a redundancy strategy — if one reproduction proves intractable on the mk_1 timeline, the platform still demonstrates the concept on the remaining two.

From those baselines, users can introduce Bayesian components into the existing models — for example, variational layers (Blundell et al., 2015), Monte Carlo dropout (Gal & Ghahramani, 2016), Flipout layers, or full Bayesian neural network replacements — and retrain, comparing the resulting posteriors against the original deterministic baselines. This is the proof of concept for mk_1. The longer-term goal is a platform where epistemic uncertainty can be explored systematically across model classes, framing a single underlying question: can this model be improved, or has it reached its epistemic limit?

Bayesian Analysis: Epistemic Exploration vs. Point Estimates

Before describing the experiments themselves, it is worth stating clearly why FORGE is built around Bayesian inference rather than ordinary deterministic models. The reason lives in the difference between a single prediction and a posterior distribution over predictions — between a point estimate that hides what the model does not know, and a distribution that makes its ignorance legible.

A conventional neural network, once trained, returns one number per input: the genre is hip-hop with probability 0.83; the phonon DOS at 200 cm−1 is 0.014; this event is signal-like with score 0.91. These are point estimates. They are the most likely value under the trained weights, but they reveal nothing about how confident the model would be if the same input were shown to a slightly different but equally valid version of the same network — one trained on a different bootstrap of the data, or initialized with different random seeds, or given a slightly different architecture. In other words, point estimates collapse away the model's epistemic uncertainty: the uncertainty arising from incomplete knowledge, finite training data, or genuine ambiguity in the decision boundary.

Bayesian inference replaces the single set of trained weights with a posterior distribution over weights given the data: p(w | D). Every prediction now produces not a single number but a distribution of plausible predictions, one for each sample drawn from that posterior. The width of that distribution is the model's epistemic uncertainty made visible. A narrow posterior at a given input means the model's predictions are stable across the space of plausible weight configurations — the model is genuinely confident, and that confidence is earned. A wide posterior means different equally-valid versions of the model would disagree about the answer — the model's apparent confidence in a point estimate would be borrowed, not earned.

This is the diagnostic capability FORGE exposes to users. The visualization below shows a single hypothetical prediction in both modes: as a point estimate (left), and as a Bayesian posterior (right). The point estimate looks confident. The posterior shows the model's actual uncertainty — and crucially, it shows the point estimate sitting near the edge of the credible region, suggesting the model's apparent confidence is not as well-supported as it looks.

Point Estimate vs. Bayesian Posterior

Figure 1. Left: a deterministic point estimate reports a single number (0.83) with no width. Right: the same problem solved with Bayesian inference yields a full posterior — here roughly centered at 0.62, with a 95% credible region spanning ~0.30 to ~0.88. The point estimate sits near the upper edge of the credible region; the posterior tells the user this prediction is less well supported than the deterministic output suggested. This is the kind of second-look diagnostic FORGE makes routine.

The cost of moving from a point estimate to a posterior is computational. Sampling from a posterior — whether via Markov Chain Monte Carlo (HMC, NUTS; Neal, 2011; Hoffman & Gelman, 2014), variational approximation, dropout-as-Bayesian, or last-layer Gaussian heads (Kristiadi et al., 2020; Daxberger et al., 2021) — takes longer than a single forward pass. FORGE addresses this with a preloaded baseline architecture where most of the model is deterministic and only the final classification or regression layer is Bayesian. This last-layer configuration is fast enough to retrain and resample within the timescale of an interactive session, while still surfacing the epistemic structure of the model's decision boundary — which is, after all, where the interesting questions live.

The remainder of this overview describes how this Bayesian-exploration capability is delivered: which three experiments are reproduced, what users see during exploratory data analysis, and how the model-building interface lets users introduce Bayesian components into the baselines.

The Three Experiments

(1) Music genre recognition — CNN with Bayesian classification head

The genre-recognition experiment extends the BEARDOWN architecture (Herling & Attili, 2025): a multimodal CNN that classifies 30-second audio clips into one of ten genres using the GTZAN dataset (blues, classical, country, disco, hip-hop, jazz, metal, pop, reggae, rock). The model uses two parallel encoders — a convolutional encoder on spectrogram images and a dense encoder on 58 engineered audio features (MFCCs, spectral centroid, chroma statistics, rhythmic descriptors) — fused into a single representation and passed through a Bayesian classification head. The original work introduced the Robust Ranking Metric (RRM), a composite score combining accuracy, fold stability, and posterior variance, validated against accuracy alone for model selection. Foundational work on CNN-based genre recognition (Sridhar, 2024) and Bayesian approximation via dropout (Gal & Ghahramani, 2016) anchors the methodology. FORGE preloads the trained baseline (target ~76% validation accuracy, the achieved BEARDOWN performance) and exposes the Bayesian-head hyperparameters as user-tunable knobs for posterior exploration.

(2) Phonon density-of-states regression — equivariant graph neural network

The phonon experiment reproduces the Euclidean neural network architecture of Chen et al. (2021): an E(3)-equivariant graph network that predicts phonon density-of-states (DOS) curves from crystal structures alone, using only atomic species and positions as input. The model is trained on ~1,500 crystalline solids curated from the DFPT phonon database of Petretto et al. (2018) via the Materials Project. The published baseline reports that 70% of test materials fall within 10% relative error on the average phonon frequency. Crucially, the published model produces point predictions only — no uncertainty quantification, no calibration metrics. FORGE's contribution on this experiment is precisely that gap: a Bayesian extension of the architecture (e.g., a Bayesian last-layer head over the 51-point DOS output) producing calibrated credible intervals on the phonon DOS curve and on derived thermodynamic quantities such as vibrational entropy and heat capacity. Calibration coverage on the held-out test set becomes the load-bearing metric beyond raw MSE.

(3) ATLAS Long-Lived Particle (LLP) detection — displaced muon-spectrometer vertices

The third experiment applies FORGE to displaced-vertex searches for Long-Lived Particles in the ATLAS detector at the LHC. The reproduction draws on prior thesis work on hidden sector scalars producing displaced muon-spectrometer vertices (MSVtx), characteristic of decays where the parent particle's lifetime is long enough to traverse measurable detector distance before decaying. The baseline model is a deterministic multilayer perceptron trained to discriminate signal events (HSS→LLP) from QCD background. The Bayesian extension adds posterior inference (full HMC over the output layer was used in the author's prior work) to surface where the classifier is genuinely uncertain versus confidently wrong — an epistemic distinction that point predictions cannot make. This is also the experiment most directly tied to the author's ongoing ATLAS research and will benefit from the same RRM-style reliability metric developed in the genre recognition project.

EDA Pipeline

When a user opens an experiment in FORGE, they first land on the Exploratory Data Analysis view for that experiment's dataset. The EDA view is dataset-specific but follows a consistent schema across the three experiments: per-feature distributions, class balance (where applicable), missing-data audits, and any pre-flagged anomalies the author documented during reproduction.

For the genre recognition experiment, EDA surfaces: per-genre spectrogram averages (the mean STFT image per class, viridis-colored), MFCC-coefficient distributions (mean and variance of each of the 20 MFCC bands, faceted by genre), missing-modality alignment summary (~10% of GTZAN tracks fail spectrogram–feature alignment in the original pipeline, a fact users see explicitly), and per-class sample counts after alignment.

For the phonon DOS experiment, EDA surfaces: the periodic-table distribution of training elements (a heatmap over 64 unique atomic species), distribution of phonon DOS curve shapes (clustered by structural family), bandgap and density covariates from the Materials Project metadata, and a per-element per-frequency mean DOS surface showing where the model has dense training coverage versus sparse regions where extrapolation will dominate.

For the ATLAS LLP experiment, EDA surfaces: kinematic feature distributions (vertex displacement, transverse momentum, invariant mass, isolation variables) split between signal MC and background data, class imbalance summary (signal events are ~10−3–10−4 of background), the ABCD-plane density structure used for closure validation, and the cutflow yield table showing how preselection cuts reshape the population.

All EDA plots are rendered server-side and cached; the user does not retrain anything to reach the EDA view. EDA is the user's onramp to a dataset they may not have seen before.

Model Building & Retraining

After EDA, the user moves to the Model view, which shows the baseline architecture diagrammed layer-by-layer with the existing Bayesian/deterministic split color-coded. For each model layer, the user sees: what it does, what its input/output dimensions are, whether it is currently deterministic or Bayesian, and what modifications FORGE supports.

The available modifications fall into a small, finite list of Bayesian techniques (the exact menu depends on what proves applicable to each architecture during mk_1 development):

  • Monte Carlo dropout (Gal & Ghahramani, 2016) — interpret dropout at test time as approximate variational inference; cheap and drop-in for most architectures.
  • Variational layers (Flipout) — replace a dense layer with a variational equivalent that maintains a Gaussian posterior over its weights; used in the BEARDOWN classification head.
  • Last-layer Bayesian inference — freeze the deterministic feature extractor and place a posterior over only the output layer weights. Fast, HMC-tractable, and often sufficient for surfacing epistemic uncertainty at decision boundaries.
  • Full Bayesian Neural Network — replace all layers with Bayesian equivalents. Expensive but maximally expressive; typically reserved for small architectures or as a stretch comparison.

The user selects a configuration, the system retrains (or fine-tunes from the deterministic baseline where applicable), and the resulting posterior is surfaced in a Posterior view: per-prediction credible intervals, calibration coverage curves, and side-by-side comparison against the deterministic baseline. The retraining loop is intended to be fast enough for meaningful exploration — on the order of minutes, not hours — which constrains the Bayesian variants FORGE can realistically support and is part of why last-layer methods are emphasized.

All trained model artifacts and their posterior samples are saved per-user so users can return to a previous configuration, compare two configurations, or share a configuration with a collaborator via URL.

What FORGE is Not

Scope boundaries that matter for mk_1:

  • Not a notebook environment. FORGE is not Jupyter-in-the-browser. Users cannot write arbitrary code; they choose between documented Bayesian configurations.
  • Not a general-purpose training framework. The three experiments are first-class; new arbitrary datasets are not.
  • Not a paper repository. FORGE does not host the source papers themselves; it cites them and links to canonical versions.
  • Not a replacement for domain expertise. The EDA and posterior views surface diagnostic information, but interpretation still requires the user to understand their domain. FORGE is a tool for trained researchers, not a black-box auto-ML product.

Three-Repository Structure

As described on the Home page, the project spans three repositories:

  1. Documentation — this repo. Carries the proposal, schedule, branding, and write-up.
  2. Experiments — research code and reproductions. Holds the actual reproduction code for the three baselines plus the Bayesian extensions.
  3. Software — the deployed application. Holds the frontend, backend, worker, and calibration components of the deployed FORGE platform.
