Project Timeline

This page presents the 13-week project schedule. Major activity blocks are grouped by phase: Planning, Design / Implementation, Testing, Write-up, and Deliverables. Specific calendar dates are bound to the Week 0 anchor in the Gantt chart.

Weekly Schedule

  • Week 0 — Intro. Course orientation. Bootstrap the three project repositories. Initial mentor sync to confirm scope.
  • Week 1 — Planning. Lock project scope. Submit proposal v1 with the milestone schedule and Gantt. Identify integration risks early.
  • Weeks 2–8 — Design / Implementation. Seven-week build phase with one substantive deliverable per week:
    • W2: Architecture sketch; calibration-tier scaffold
    • W3: Backend skeleton, data loader, posterior interface
    • W4: Hernández-Lobato proof-of-concept reproducing baseline metrics
    • W5: Frontend MVP wired to backend; demo gallery shell
    • W6: FAIR Universe HiggsML evaluation pipeline running end-to-end
    • W7: Worker process and hyperparameter sweep harness
    • W8: Full integration pass; end-to-end smoke test passing
  • Weeks 9–10 — Testing. W9 covers unit and integration tests plus calibration sanity checks. W10 is user-facing testing, bug triage, and UX polish — this is the slack week if any earlier deliverable slips.
  • Week 11 — Write-up. Final paper drafted and revised. iShowcase poster and demo materials prepared. Practice run of the live demo.
  • Week 12 — Deliverables. Final submission. iShowcase presentation. Repository freeze and tag v1.0 cut across all three repos.

Risk Management

The schedule reserves Week 10 explicitly as a recovery buffer. If a Design / Implementation milestone slips by one week, the integration smoke test (W8) shifts into W9 and the testing window compresses to W10 only. A two-week slip triggers a scope-cut conversation with the advisor — the FAIR Universe HiggsML evaluation tier (W6) is the documented descope candidate, since the calibration tier (W2–W4) is the load-bearing piece of the writeup.

Tracking

This schedule is mirrored in the Gantt chart, whose source of truth is data/gantt.json in this repository. The Gantt is updated weekly; git commits provide the frozen paper trail.
