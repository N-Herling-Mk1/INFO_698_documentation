FORGE Contract

The FORGE contract is the two-sided agreement between an experiment and the observatory: what an experiment must supply (inbound, tiered by necessity), and what FORGE owes back (outbound, the four aspects). The contract is written in φ-space — the frozen backbone’s penultimate features — and that choice of currency is what separates FORGE itself from the widgets that feed it.

The contract in one line

FORGE consumes (φ_train, y_train, likelihood, τ) and returns the four observatory aspects. Everything else is either a cache of that core, an adapter into it, or a display beside it.

Inbound — the four tiers

Tier 0 Statistical core required

φ_train (N×d penultimate features from a frozen, deterministic backbone), y_train aligned to it — alignment verified, not assumed — a declared likelihood family (softmax classification vs. Gaussian regression; it selects the LLLA/HMC path), and a prior/τ configuration with its tau_range. Every one of the four aspects is computable from this tier alone.

Tier 1 Fitted cache derivable — shipped for speed

The fitted LLLA head, the GGN eigenbasis (ggn_eig), cached eigen-projections of the examples, the capabilities array, and the metrics card. This tier is fit: features → bundle — no new information, just Tier 0 precomputed so the τ-knob recomputes in-browser instead of refitting server-side.

Tier 2 Input-space adapters optional — widget side

Backbone checkpoint + architecture, feature scaler, label map. Their single job is mapping new raw inputs into φ-space: the Drop Deck, guest projection, and rung-2 attribution (dφ/dx) all cross this line; rung-1 attribution (dσ/dφ) does not. FORGE core never touches raw inputs.

Tier 3 Display artifacts optional — X-space

eda_stats.json + figures for the feature-stats bay. These live in input space (named raw features), not φ-space — derivable from the raw data, never from φ_train. A separate artifact stream, documented here precisely so it is not mistaken for part of the core.

The bundle, mapped to tiers

The shipping unit is the experiment bundle. Each file resolves to exactly one tier and one consumer:

Bundle fileTierConsumed by
phi_train.npy0data-fraction refits · HMC · LLLA (re)fit
y_train.npy0HMC likelihood · data-fraction refits
ggn_eig.npz1eigenspectrum · in-browser τ recompute
metrics1meta card (accuracy / ECE / regression set)
weights + arch2raw input → φ (Drop Deck, guest projection, rung-2 attribution)
scaler2raw input → φ (same path)
label_map2class names on verdict cards and posterior bars

Validity rules. The backbone is frozen and deterministic (φ is stable); the φ/y alignment check is enforced at build time (max |Δφ| under tolerance, or the bundle is rejected — misalignment is silent otherwise); the likelihood family is declared, never inferred; and capabilities lists only what the shipped artifacts actually support.

Outbound — what FORGE owes back

Given a valid Tier 0/1 bundle, FORGE serves the four observatory aspects through /api/forge/{meta, posterior, datasweep, hmc}. The meta endpoint reports the bundle identity, example count, tau_range, and metrics card; hmc is environment-gated for public deploys. The capabilities array gates the dashboard bays: a missing artifact leaves its bay staged — visibly present, honestly inert — never a 500. (Attribution is the live example: rung-2 implemented, bay staged until attribution.npz ships in a bundle.) The widget-side /api/predict route documented in the MVP plan is a Tier-2 contract, deliberately separate from these four.

The boundary

The widget is not FORGE. Audio drop, crystal builder, CSV upload — those are Tier-2 adapters, and they end at φ. FORGE begins at φ. Nothing in Tiers 2–3 is required for the observatory to function; nothing in Tiers 0–1 knows raw inputs exist.

The executable contract planned

The tutorial experiment adds live, backend-driven retraining (new architecture or parameters, capped at roughly five minutes per run). That changes the contract’s nature: it stops being a one-time artifact drop and becomes a function the backend executes — every retrain must re-emit Tier 0 → 1 programmatically: recompute φ_train, refit the head, re-eigendecompose, refresh projections and capabilities. Same contract, run on a loop.
